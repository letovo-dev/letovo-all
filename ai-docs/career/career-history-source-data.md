# Данные, нужные для восстановления карьерной истории

Мне нужна одна согласованная выгрузка в UTF-8 CSV (разделитель `;`) или XLSX с четырьмя листами/файлами. Пожалуйста, не присылайте пароли, токены, телефоны или другие лишние персональные данные.

## Почему выгрузка нужна целиком

Я проверил продовую базу 2026-08-05. Истории должностей в ней нет: таблица `user_posts` содержит одну тестовую строку, `user_brigades` — две, справочник `post` — одно значение «самый главный». Зарплатные транзакции начинаются только с 2026-06-30 и не позволяют определить роль однозначно (выплата 300 соответствует 17 разным ролям). Даты достижений (`user_achivements`, с 2025-07-01) датируют награждения, а не назначения — сейчас карьерные карточки строятся именно на этой подмене, поэтому и выглядят неверно.

В базе есть только текущий срез: 1997 пользователей, у 1637 заполнена текущая роль. Всё, что было раньше, восстановить изнутри системы нечем.

## Справочники, к которым нужно приводить значения

Отделы (`department`), 12 значений:

`IT`, `Управление`, `Инженерный`, `ДСО`, `Арт`, `Научный`, `Проект 11`, `Клуб`, `Бюро находок`, `Дизайн`, `X`, `[НЕТ ДОСТУПА]`.

Роли (`roles`), 56 значений: в большинстве отделов действует лестница `стажер` → `Джун` → `Мидл` → `Сеньор` → `Тимлид`, плюс отдельная роль `Старший`; в отделах `Клуб` и `Бюро находок` заведена только `Старший`, в `Дизайн` — `стажер`/`Джун`/`Мидл`. Роль уникальна парой «отдел + название», поэтому в выгрузке всегда указывайте оба поля.

Если в ваших данных встречаются названия отделов или ролей вне этих списков, не подбирайте похожее — вынесите их в файл `role_mapping` (лист 4).

## 1. `career_periods`

Одна строка — один период в одном отделе. Если в периоде у человека две должности, период всё равно один.

| Поле | Обязательно | Формат | Пример |
| --- | --- | --- | --- |
| `external_period_id` | да | стабильный идентификатор периода | `ivanov-2025-g2-design` |
| `username` | да | существующий логин Letovo Corp | `ivanov_i` |
| `department` | да | точное название отдела из списка выше | `Дизайн` |
| `brigade` | нет | точное имя бригады; пусто, если её не было | `Био-химический` |
| `started_at` | да | ISO 8601: `YYYY-MM-DD` или `YYYY-MM-DDTHH:MM:SS+03:00` | `2025-09-01` |
| `ended_at` | нет | тот же формат; пусто только у текущего периода | `2026-05-31` |
| `chapter` | нет | отображаемая глава или смена | `Смена 2` |
| `academic_year` | нет | год окончания учебного периода | `2026` |
| `source_note` | нет | ссылка/краткое основание для ручной сверки | `приказ 42` |

У одного пользователя периоды не должны пересекаться. Для периода без точной даты допустимо указать границу главы, пометив строку в `source_note` как приблизительную.

Названия бригад присылайте полным списком даже при отсутствии истории: справочник `brigade` в базе пуст, заводить его придётся с нуля.

## 2. `career_positions`

Одна строка — одна должность в периоде из `career_periods`. Так сохраняются «Должность 1» и «Должность 2» из макета.

| Поле | Обязательно | Формат | Пример |
| --- | --- | --- | --- |
| `external_period_id` | да | ссылка на `career_periods.external_period_id` | `ivanov-2025-g2-design` |
| `position_order` | да | целое число от 1 | `1` |
| `role` | да | точное название роли из справочника | `Мидл` |
| `is_primary` | да | `true`/`false`; только одна `true` на период | `true` |
| `source_note` | нет | основание, если роль не заведена в системе | `архив кадров` |

Несколько должностей — не редкий случай: сейчас у 174 пользователей больше одной роли, а у 53 роли сразу в 2–3 отделах. Если по вашим данным это ошибка, отметьте таких пользователей отдельно — иначе я перенесу их как есть.

## 3. `career_skills`

Одна строка — навык/достижение, связанный с периодом. Если исторические навыки переносить не требуется, пришлите файл с заголовками и без строк, а в `source_note` периода отметьте `skills-not-restored`.

| Поле | Обязательно | Формат | Пример |
| --- | --- | --- | --- |
| `external_period_id` | да | ссылка на период | `ivanov-2025-g2-design` |
| `achievement_id` | да | существующий ID достижения Letovo Corp | `42` |
| `awarded_at` | нет | ISO 8601; если известна дата вручения | `2026-02-18` |
| `stage` | нет | целое число, по умолчанию `1` | `4` |
| `source_note` | нет | основание/комментарий | `реестр награждений` |

## 4. `chapters` — календарь глав и смен

Нужен отдельно, потому что в базе главы фактически отсутствуют: справочник `calendar` содержит одну строку `zero` на период 2024-04-06 → 2026-04-06, из-за чего все карточки показывают одну и ту же главу. Реальные смены заведены только за 2026 год (`Смена 1`–`Смена 4`, 2026-06-27 → 2026-08-15), а достижения есть уже с 2025-07-01.

| Поле | Обязательно | Формат | Пример |
| --- | --- | --- | --- |
| `chapter` | да | отображаемое название | `Смена 2` |
| `start_date` | да | `YYYY-MM-DD` | `2025-07-10` |
| `end_date` | да | `YYYY-MM-DD` | `2025-07-20` |
| `academic_year` | нет | год | `2025` |

Периоды не должны пересекаться. Если за прошлые сезоны деления на смены не было, пришлите одну строку на сезон с понятным названием.

## Перед передачей

- Проверьте, что каждый `username` существует в текущей БД, а ссылки между файлами не имеют пропусков.
- Укажите, какой период считать текущим; допускается только один текущий основной период на пользователя.
- Приложите 3–5 контрольных пользователей с ожидаемым результатом: какие карточки, в каком порядке и с какими должностями должны отображаться.
- Сохраните исходные файлы без автоформатирования дат и без объединённых ячеек. Архив `.zip` с CSV и коротким `README` приемлем.

После получения я сначала прогоню валидацию без записи в БД и верну отчёт: неизвестные пользователи, роли, отделы и бригады, пересечения дат, дубликаты и количество строк, готовых к импорту.

## Если выгрузки не будет

Тогда история не восстанавливается — это не вопрос доработки кода. В этом случае я импортирую только текущее состояние: у каждого пользователя появится один открытый период с его нынешними отделом и ролью, а раздел «Карьера» начнёт накапливать историю с даты внедрения. Прошлые карточки останутся пустыми. Скажите, приемлем ли такой вариант, чтобы я не блокировал остальную работу.
