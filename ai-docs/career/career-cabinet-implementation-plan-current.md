# Актуальный план реализации карьерного кабинета

Этот документ заменяет предыдущий `career-cabinet-implementation-plan.md` для реализации и приёмки.

## Цель

Показывать в личном кабинете подтверждённую текущую и прошлую карьеру пользователя: периоды, отдел, бригаду, одну или несколько должностей и навыки.

## Границы

- Дерево прокачки сотрудника и дерево корпорации не входят в эту поставку.
- Исправление ранее обнаруженных дефектов вне новой карьерной модели не входит в эту поставку.
- У пользователя может быть не более одного карьерного периода в любой момент времени, включая разные отделы. Пробелы допустимы и означают отсутствие подтверждённых исторических данных.

## Задачи

- [ ] Утвердить контракт карьерного периода и правила исходной выгрузки: непересекающиеся даты, один отдел на период, несколько должностей только внутри периода. → Проверка: утверждены примеры пустой, текущей и прошлой карточек.
- [ ] Добавить временную модель периодов, должностей, бригад и навыков с внешними ключами, индексами и ограничением непересечения периодов пользователя. → Проверка: миграция накатывается и откатывается на чистой БД.
- [ ] Подготовить dry-run и идемпотентный импорт `career_periods`, `career_positions`, `career_skills`, `chapters`; отклонять перекрывающиеся периоды до записи. → Проверка: отчёт содержит количество импортируемых, отклонённых и неизвестных записей с причинами.
- [ ] Начать сохранять новые назначения и переводы в новой временной модели одновременно с обновлением текущей `user.role`. → Проверка: новый переход создаёт закрытый предыдущий и один открытый следующий период.
- [ ] Добавить административные API для создания, изменения и закрытия карьерных периодов с авторизацией и валидацией дат. → Проверка: контрактные тесты покрывают права, неизвестные справочники и пересечение периодов.
- [ ] Добавить `GET /user/career/:username`: возвращать периоды от текущего к прошлому, главу/год, отдел, бригаду, упорядоченные должности и навыки; пустая история — `200` с пустым массивом. → Проверка: API совпадает с контрольной выгрузкой.
- [ ] Добавить типизированный API-клиент и состояние загрузки/ошибки во frontend; удалить production-зависимость карьерного блока от агрегированного achievement API и mock-данных. → Проверка: карьерный экран запрашивает только новый endpoint.
- [ ] Доработать карьерные карточки личного кабинета: текущая раскрыта первой, прошлые свёрнуты; отображаются отдел, бригада, «Должность 1…N», глава/год, новые и ранее полученные навыки, а также пустое состояние. → Проверка: desktop и mobile соответствуют макетам для контрольных пользователей.
- [ ] Принять продуктовое решение о read-only отображении карьеры на публичном профиле и покрыть утверждённый вариант e2e-проверкой. → Проверка: публичный маршрут либо показывает данные, либо не выполняет карьерный запрос согласно решению.
- [ ] Провести staging-импорт, построчную сверку контрольных пользователей, затем production rollout с резервной копией; прогнать миграционные, API и frontend-проверки. → Проверка: CI зелёный, `ya-yara` одобрила PR, данные контрольных пользователей совпадают с выгрузкой.

## Готово, когда

- [ ] История не выводится эвристикой из дат достижений.
- [ ] В кабинете корректно показаны текущие и прошлые периоды без фиктивного заполнения пробелов.
- [ ] Исторические периоды одного пользователя не пересекаются, в том числе между отделами.
