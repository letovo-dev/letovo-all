# Макеты редактора статей (issue #209)

Два HTML-макета редактора статей — чтобы заказчик попробовал оба и выбрал, какой делать
по-настоящему. Это прототипы: они ничего не отправляют на сервер и не входят в сборку фронтенда.

## Как открыть

```bash
# из корня репозитория
xdg-open docs/prototypes/article-editor/index.html   # Linux
open docs/prototypes/article-editor/index.html       # macOS
```

Никакой сборки и npm не нужно — достаточно браузера.

Картинка в демо-статье и шрифт `Caleo` подтягиваются из сабмодуля `frontend/` по относительному
пути. Если сабмодуль не выкачан (`git submodule update --init frontend`), макеты всё равно
работают: будет системный шрифт и «битая» картинка. Видео в демо-статье — внешняя ссылка, без
интернета плеер останется пустым.

## Что внутри

| Файл | Назначение |
| --- | --- |
| `index.html` | Страница сравнения: описание вариантов и таблица отличий |
| `variant-a-markdown.html` | **Вариант A** — Markdown с панелью форматирования и превью справа |
| `variant-b-wysiwyg.html` | **Вариант B** — визуальный (WYSIWYG) редактор поверх макета статьи |
| `shared/article-preview.css` | Стили статьи, перенесённые 1-в-1 из `Articles.module.scss` |
| `shared/editor-chrome.css` | Палитра, шрифт и элементы управления сайта из `globals.scss` |
| `shared/markdown.js` | Мини-рендерер Markdown → HTML и обратный сериализатор HTML → Markdown |
| `shared/sample-article.js` | Общий fixture: заголовки, списки, таблица, цитата, код, картинка, видео, secret/download-ссылки |

## Что макеты решают из issue

1. **Оформление под сайт.** Обвязка редактора использует палитру и шрифт сайта
   (`--orange #fb4724`, `Caleo`) вместо дефолтного вида `@uiw/react-md-editor`.
2. **Превью = сайт.** Оба макета рендерят статью правилами из `Articles.module.scss` внутри
   контейнера той же ширины (519px на десктопе, 390px на мобильном), с той же семантикой, что
   у `ReactMd.tsx`: `![](file.mp4)` → `<video>`, ссылки на файлы → download-ссылки, «secret link»
   → нестилизованный текст, таблицы в скроллящейся обёртке. Переключатель «Десктоп / Мобильный»
   в превью показывает обе геометрии.
3. **«Может, вместо сырого md — просто текстовый редактор?»** Это вариант B. Важно: формат
   хранения он не меняет — статья по-прежнему сохраняется в `.md` (в макете это видно в блоке
   «Показать Markdown, который уйдёт в файл статьи»), поэтому существующие статьи остаются
   читаемыми, а серверное API трогать не нужно.

## Что проверить заказчику

- Набрать абзац, заголовок, список, вставить таблицу и картинку — в обоих вариантах.
- Переключить превью в «Мобильный»: не разъезжается ли статья.
- В варианте B — вставить текст из Word / Google Docs и раскрыть «Показать Markdown»:
  устраивает ли то, что сохранится.
- Открыть демо-статью и сравнить со страницей `/articles` на проде: одинаково ли выглядит.

## Ограничения макетов

- `shared/markdown.js` — намеренно маленький парсер (примерно 250 строк) для показа, а не замена
  продового пайплайна. В реализации остаются `remark-gfm` + `rehype-raw` + `rehype-sanitize`;
  сырой HTML в макете пропускается по короткому списку тегов.
- Вложенные списки, сноски и HTML-атрибуты в макете упрощены.
- Вариант B использует `document.execCommand` — для прототипа этого достаточно, но в реализации
  нужен нормальный редактор (например, TipTap/ProseMirror) с сериализацией в Markdown.
- Кнопки «Сохранить», «Загрузить .md», «Скачать .md» — заглушки.

## Что делать после выбора

Независимо от выбранного варианта первым шагом идёт общий `ArticleContent`-рендерер и общий набор
стилей статьи, которые используют и `/articles`, и превью редактора — сейчас это два независимых
пайплайна (`ReactMd.tsx` против `@uiw/react-md-editor`), и именно поэтому превью не совпадает с
сайтом. Дальше — реализация выбранного варианта и parity-тесты на
headings / lists / tables / links / images / video / raw HTML плюс проверка, что существующие
`.md`-статьи открываются и пересохраняются без потерь.
