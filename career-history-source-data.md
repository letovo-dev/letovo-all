# Данные, нужные для восстановления карьерной истории

Мне нужна одна согласованная выгрузка в UTF-8 CSV (разделитель `;`) или XLSX с тремя листами/файлами. Пожалуйста, не присылайте пароли, токены, телефоны или другие лишние персональные данные.

## 1. `career_periods`

Одна строка — один период в одном отделе. Если в периоде у человека две должности, период всё равно один.

| Поле | Обязательно | Формат | Пример |
| --- | --- | --- | --- |
| `external_period_id` | да | стабильный идентификатор периода | `ivanov-2025-g2-design` |
| `username` | да | существующий логин Letovo Corp | `ivanov_i` |
| `department` | да | точное название отдела или `department_id` | `Дизайн` |
| `brigade` | нет | точное имя бригады; пусто, если её не было | `Био-химический` |
| `started_at` | да | ISO 8601: `YYYY-MM-DD` или `YYYY-MM-DDTHH:MM:SS+03:00` | `2025-09-01` |
| `ended_at` | нет | тот же формат; пусто только у текущего периода | `2026-05-31` |
| `chapter` | нет | отображаемая глава | `Глава 2` |
| `academic_year` | нет | год окончания учебного периода | `2026` |
| `source_note` | нет | ссылка/краткое основание для ручной сверки | `приказ 42` |

У одного пользователя периоды не должны пересекаться. Для периода без точной даты допустимо указать границу учебной главы, но такие строки нужно пометить в `source_note` как приблизительные.

## 2. `career_positions`

Одна строка — одна должность в периоде из `career_periods`. Так сохраняются «Должность 1» и «Должность 2» из макета.

| Поле | Обязательно | Формат | Пример |
| --- | --- | --- | --- |
| `external_period_id` | да | ссылка на `career_periods.external_period_id` | `ivanov-2025-g2-design` |
| `position_order` | да | целое число от 1 | `1` |
| `role` | да | точное название роли или `role_id` | `Младший научный сотрудник` |
| `is_primary` | да | `true`/`false`; только одна `true` на период | `true` |
| `source_note` | нет | основание, если роль не заведена в системе | `архив кадров` |

Если название отдела или роли отличается от справочника Letovo Corp, приложите отдельную таблицу `role_mapping` с колонками `source_department`, `source_role`, `target_department_id`, `target_role_id`. Не следует угадывать соответствия по похожему названию.

## 3. `career_skills` (нужен для полного соответствия раскрытой карточке)

Одна строка — навык/достижение, связанный с периодом. Если исторические навыки переносить не требуется, предоставьте файл с заголовками и без строк, а в `source_note` периода отметьте `skills-not-restored`.

| Поле | Обязательно | Формат | Пример |
| --- | --- | --- | --- |
| `external_period_id` | да | ссылка на период | `ivanov-2025-g2-design` |
| `achievement_id` | да | существующий ID достижения Letovo Corp | `42` |
| `awarded_at` | нет | ISO 8601; если известна дата вручения | `2026-02-18` |
| `stage` | нет | целое число, по умолчанию `1` | `4` |
| `source_note` | нет | основание/комментарий | `реестр награждений` |

## Перед передачей

- Проверьте, что каждый `username` существует в текущей БД, а ссылки между тремя файлами не имеют пропусков.
- Укажите, какой период считать текущим, если у пользователя есть незакрытая строка; допускается только один текущий основной период.
- Приложите 3–5 контрольных пользователей с ожидаемым результатом: какие карточки, в каком порядке и с какими должностями должны отображаться.
- Сохраните исходные файлы без автоформатирования дат и без объединённых ячеек. Архив `.zip` с тремя CSV и коротким `README` приемлем.

После получения я сначала прогоню валидацию без записи в БД и верну отчёт: неизвестные пользователи/роли/отделы, пересечения дат, дубликаты и количество строк, готовых к импорту.
